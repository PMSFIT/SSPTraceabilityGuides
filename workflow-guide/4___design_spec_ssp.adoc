== Design Specification with SSP, SSP LS Traceability

The SSP standard <<SSP201>> is intended to support

.	the exchange of interconnected simulation models and their parameterization, and
.	the simulation design by specifying empty components through their interface templates

In a simulation request, it is generally sufficient to describe the simulation task and its objective.
However, no further specifications are made regarding the type of simulation and the models used (as in the example in <<im-ssp-trace-structure>> and <<im-stmd-links>>).

However, more detailed information, such as design specifications or parts of the implementation and test environments, is often specified.
A simple example is provided in the chapter examples (see <<im-dc-motor>> and `SSP-Trace-DesignSpec.ssp`), the electromagnetic part of the DC motor is transferred as an FMU, while only the shell description with interfaces is provided for the mechanical part.
It makes sense to use SSP LS Traceability directly as a container for the artifacts here.
The FMUs whose interconnection is specified as SSD are linked as inputs to the implementation phase (<<im-designspec>>).
This approach makes it possible to trace what was input and what was created in the simulation task itself.
